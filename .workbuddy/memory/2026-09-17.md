### 用户反馈

### 排查结论（证据链完整）
1. **根因**：旧版 server.js 的 initDatabase() 在**每次启动时 DROP TABLE**（transactions/holdings/ai_analysis/fund_nav/funds/user_configs），重建空表。start.bat 用 `node server.js` 启动 → 用户每次用 start.bat 启系统都会清空数据。已在本日修复（改为幂等建表）。
2. **证据**：
   - 今早接手时 transactions/holdings/funds/fund_nav 已全 0，仅 analysis_logs=50（该表不在 DROP 列表，得以幸存）→ 与"server.js 启动清表"完全吻合
   - analysis_logs 50 条全部是 9/17 10:00–12:00（北京时间）生成，无 9/16 记录 → 昨天的数据在 9/17 上午某次 server.js 启动时被清（Deploy Center 日志显示 11:38 前 3000 端口为外部进程 pid=73424，即 start.bat 起的 server.js）
   - 前端 Trading.vue 为纯模拟页（无 API 调用）；唯一写 transactions/holdings 的入口是"立即分析"（POST /api/ai/analyze），定时分析只写 analysis_logs → 昨天用户操作的数据确实落在过库里，后被清
   - 数据库文件创建于 9/16 11:07（未删文件，内容被覆盖）；回收站 4027 条元数据无 fund 相关；无备份；FileHistory 未启用；VSS 需管理员
